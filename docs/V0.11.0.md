# V0.11.0 — Agents

V0.11 introduces Agents as role-oriented OrchestraX components that consume the effective V0.10 instruction rails.

## Default agents

- `java-dev`
- `android-dev`
- `web-angular-dev`
- `web-vanilla-dev`

Agents are configuration data under `defaults/agents/`, not hard-coded orchestration logic.

Each agent declares:

- identity and version
- role and description
- capabilities
- project applicability
- required/optional instruction dependencies
- overrideability and priority
- agent behavior content

## Layering

Agents may be supplied at the same layers as instructions:

```text
OrchestraX Defaults → User → Workspace → Project → Effective Agent
```

An applicable lower-level agent may override an overrideable definition with the same ID. Non-overrideable defaults remain authoritative.

## Instruction dependencies

Agents reference rails by ID and version range. OrchestraX resolves those references against V0.10's effective instructions and reports missing required dependencies.

Skills are intentionally not introduced yet; that is the V0.12 milestone.

## Commands

```text
neo agent list <project>
neo agent show <project> <agent-id>
neo agent effective <project>
neo agent validate <path>
```

AI-facing:

```text
@agents
@agents for MoneyMap
@agent java-dev for MoneyMap
```

## Provider integration

Provider synchronization now includes applicable resolved agents and their instruction dependencies alongside the effective rails, project intelligence, Syntra context, installed packs, and handoff continuity.

Agent instruction dependencies are version-checked for exact versions and the common `^` / `~` ranges. A required dependency that is missing or incompatible is surfaced as a resolution conflict.
