# V0.13.0 — Pack Composition + Dependency Resolution

V0.13 makes Packs first-class compositions instead of flat lists of metadata.

## Pack contents

A Pack can declare:

- instructions / rails
- agents
- skills
- pack dependencies
- compatibility requirements

Every dependency has an id, version range and required/optional flag.

## Dependency resolution

OrchestraX resolves pack dependencies recursively and produces a deterministic dependency graph. It detects:

- missing packs
- incompatible pack versions
- circular pack dependencies
- missing or incompatible effective instructions, agents and skills during project composition
- project compatibility failures

Supported dependency ranges remain:

- exact: `1.0.0`
- compatible major: `^1.0.0`
- compatible minor: `~1.0.0`
- any: `*`

## CLI

```text
neo pack list
neo pack show android-kotlin-dev
neo pack graph android-kotlin-dev
neo pack validate android-kotlin-dev
neo pack compose android-kotlin-dev MoneyMap
```

`pack show` displays composition metadata. `pack graph` displays the resolved pack dependency order. `pack validate` validates the manifest and pack dependency graph. `pack compose` resolves the pack against the selected project's effective OrchestraX resources and compatibility signals.

## AI-facing model

The canonical interaction remains through OrchestraX commands rather than directly invoking Syntra internals. Pack composition is part of the same orchestration layer used to select context and provider artifacts.

## Backward compatibility

Existing packs remain valid as compositions. V0.13 extends their manifests with dependency fields while preserving their existing capabilities, agents and skills. Provider adapters continue consuming canonical effective context rather than pack-specific provider logic.
