# V0.10.0 — Default Rails / Instructions

V0.10 establishes OrchestraX Instructions as a first-class, layered configuration system. Instructions are the default rails that guide agent behavior without being hard-coded into orchestration logic.

## Sources and precedence

1. OrchestraX defaults — shipped with the toolkit.
2. User instructions — `~/.orchestrax/instructions/`.
3. Workspace instructions — `<workspace>/.orchestrax/instructions/`.
4. Project instructions — `<project>/.orchestrax/instructions/`.

A higher-level definition may replace a lower-level instruction when the lower-level instruction is `overrideable`. Non-overrideable defaults cannot be replaced by user/workspace/project definitions.

## Instruction definition

Each instruction directory contains:

```text
instruction.json
instruction.md
```

Example:

```json
{
  "id": "java/coding-standards",
  "version": "1.0.0",
  "description": "Java coding standards baseline.",
  "category": "java",
  "appliesTo": ["java"],
  "required": false,
  "overrideable": true,
  "priority": 0
}
```

## Built-in rails

- `common/coding-standards`
- `common/testing`
- `common/documentation`
- `common/git-workflow`
- `common/security-baseline`
- `java/coding-standards`
- `android/kotlin-standards`
- `web-angular/standards`
- `web-vanilla/standards`

The common security baseline is intentionally non-overrideable.

## Resolution

The Instruction Resolver selects applicable instructions from the layered sources and produces the effective rails for the current project. Applicability can be based on project identity or Project Intelligence signals such as `java`, `kotlin`, `android`, `angular`, and `typescript`.

## Diagnostics

```text
neo instruction list MoneyMap
neo instruction effective MoneyMap
neo instruction show MoneyMap common/security-baseline
neo instruction validate ./my-instruction
```

## AI-facing interface

The user addresses OrchestraX directly:

```text
@instructions
@instructions for MoneyMap
@instructions java/coding-standards for MoneyMap
```

Syntra remains internal; there is no `@syntra` command.

## Provider integration

Provider synchronization now includes the effective OrchestraX rails in provider-specific artifacts. This gives V0.9 provider adapters a canonical instruction source without making provider files the source of truth.
