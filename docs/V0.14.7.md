# V0.14.7 — Copilot Slash Command Projection via Agent Skills

V0.14.7 keeps the canonical OrchestraX AI Command model provider-neutral and changes only the Copilot projection used for slash-command discovery.

## Canonical source

AI Commands remain provider-neutral files under `commands/*.command.md`.

## Copilot projection

The Copilot provider adapter now projects each canonical AI Command into a provider plugin Agent Skill:

```text
providers/copilot/
├── plugin.json
└── skills/
    ├── package-selector/SKILL.md
    ├── package-install/SKILL.md
    └── ...
```

Each projected skill sets:

- `user-invocable: true`
- `disable-model-invocation: true`

so it is intended to appear in the Copilot `/` slash-command menu as an explicitly invoked action.

This projection uses the Agent Plugins standard portable `skills/` component rather than relying on the Copilot-specific `com.github.copilot/commands/` surface, which is not the slash-discovery path used by Agent Host sessions in this workflow.

## Scope

The canonical OrchestraX definitions remain under `neo-orchestrax/commands/`. No `.copilot`, parent-workspace, managed-project, or VS Code extension files are required by the core.

## Note

V0.14.7 establishes the provider projection and slash-discovery surface. Runtime execution remains backed by the existing provider-neutral OrchestraX command engine and CLI diagnostic bridge.
