# Neo OrchestraX V0.9.0 — Provider Adapters / Provider Artifacts

V0.9.0 establishes the provider integration boundary.

## Providers

- GitHub Copilot (`copilot`)
- Gemini / Antigravity (`gemini`)
- Claude Code (`claude`)
- Cursor (`cursor`)

## Principle

Neo OrchestraX keeps canonical project intelligence provider-neutral. Provider adapters translate that canonical context into provider-specific project artifacts.

```text
Project + Project Intelligence + Syntra + Packs + Handoff
                         |
                         v
                Provider Adapter
                  /    |    |    \
                 v     v    v     v
             Copilot Gemini Claude Cursor
```

The provider is an execution surface, not the source of truth. Syntra remains the internal persistent project-intelligence layer, while Handoff represents current continuity.

A generated artifact contains a managed marker. Existing unmanaged files are never overwritten; synchronization reports them as skipped.

## CLI

```text
neo provider list
neo provider sync MoneyMap
neo provider sync MoneyMap copilot
```

## AI-facing commands

The user talks to Neo OrchestraX:

```text
@provider-sync
@provider-sync for MoneyMap
@provider-sync copilot for MoneyMap
```

If no provider is specified, OrchestraX synchronizes all supported providers.

## Canonical context included

Provider artifacts are generated from:

- project technology signals
- installed OrchestraX packs
- confirmed/review Syntra knowledge
- latest handoff continuity, when available

Draft, rejected, and superseded Syntra entries are not promoted into provider context.
