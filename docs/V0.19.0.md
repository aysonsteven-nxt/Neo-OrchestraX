# V0.19.0 — Agent-to-Project Collaboration

V0.19.0 adds a provider-neutral execution boundary for analyzing a Project Hub User Story with an existing OrchestraX agent and persisting the result as an attributed story comment.

## Workflow

```text
User Story + Project Hub context
              |
              v
     Resolve applicable agent
              |
              v
  Resolve required instructions/skills
              |
              v
   Build analysis-only request
              |
              v
  Configured AgentExecutor adapter
              |
              v
     Validate successful response
              |
              v
  Append attributed Story JSON comment
```

The Project Hub filesystem remains the source of truth. No new database, chat store, React application, or mandatory AI SDK is introduced.

## Commands

Prepare and inspect the exact prompt without starting an AI process or changing files:

```powershell
neo story collaborate MoneyMap US-123 story-reviewer --dry-run
```

List configured executors, validate configuration, or print a starter example:

```powershell
neo executor list
neo executor validate
neo executor example
```

Execute analysis and persist the response as a User Story comment:

```powershell
neo story collaborate MoneyMap US-123 story-reviewer
neo story collaborate MoneyMap US-123 story-reviewer --executor local-readonly-agent
```

A successful comment records an author such as `agent:story-reviewer via local-readonly-agent` and includes the executor id in the comment body. Failed execution, empty output, unresolved required agent dependencies, or an unverified executor do not produce a success comment.

## Executor configuration

OrchestraX does not pick a provider or run an AI CLI by default. Configure an explicitly selected command executor in:

```text
<workspace>/.orchestrax/agent-executors.json
```

Run `neo executor example` to print the schema example. Configure the command and arguments for the selected CLI. `inputMode` is either:

- `stdin`: the prepared analysis prompt is written to standard input.
- `argument`: exactly one `{prompt}` placeholder is required in `args`.

Supported argument placeholders are `{prompt}`, `{agentId}`, `{projectId}`, `{projectName}`, `{projectPath}`, `{storyId}`, and `{workspaceRoot}`. The command is spawned without a shell. Use a native executable or runtime entrypoint appropriate to the host OS; do not rely on shell command strings.

**Security gate:** the executor must have `readOnlyVerified: true` to run. This is an operator attestation, not a sandbox implementation. Set it to `true` only after independently verifying that the configured backend's operating-system-enforced isolation prevents writes to the project. A prompt asking the model not to write files is not a security boundary. If isolation cannot be verified, keep the flag `false`; dry-run and fake-executor tests remain available. The Codex configuration investigated during this release must not be marked verified because its read-only write probe succeeded.

Executor processes have configurable timeouts and output-size limits. The process is launched with `shell: false`; credentials should be supplied through the backend's supported authentication flow, not stored in this JSON file.

## Provider neutrality

`AgentExecutor` is the stable orchestration boundary. V0.19.0 includes a configurable process adapter but does not hardcode Codex, Copilot, Claude, Gemini, a local inference server, or an AI router. Future adapters can implement the same request/result contract.

## Verification

The release tests cover prompt/context preparation, successful comment persistence, failure without comment persistence, and refusal to launch an executor whose read-only isolation has not been verified.
