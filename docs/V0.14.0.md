# V0.14.0 — AI Commands + Provider Adapter Abstraction

V0.14 makes the AI-facing command layer first-class while keeping the core provider-neutral.

## AI Commands are primary

OrchestraX now has a dedicated AI Command model separate from the CLI.

Canonical syntax:

```text
/package-selector
/package-install android-kotlin-dev for MoneyMap
/context for MoneyMap
/task start "Transaction history" "Track transaction history" for MoneyMap
/handoff for MoneyMap
/resume for MoneyMap
```

Command definitions live under the canonical, provider-neutral:

```text
neo-orchestrax/commands/
```

Each `*.command.md` file contains command metadata and the reusable prompt/instructions for the action.

The legacy `@command` syntax remains accepted by the parser for backward compatibility, but `/command` is now canonical.

## AI Command routing

A dedicated AI Command Router now:

1. parses the canonical `/command` syntax
2. resolves the command definition from `commands/*.command.md`
3. resolves the target project
4. dispatches to the corresponding OrchestraX subsystem
5. returns a structured result suitable for a provider adapter

Implemented command handlers cover packs, context, tasks, handoff/resume, instructions, agents, skills and provider sync.

## Provider Adapter abstraction

Provider adapters now expose a common contract consisting of:

- provider identity and description
- provider capabilities
- canonical project-context generation
- AI command exposure/projection metadata

The OrchestraX command itself remains provider-neutral. A provider adapter determines how, or whether, that command can be exposed through the provider's native AI surface.

No provider-specific directory or plugin is part of the OrchestraX core model.

## Manifest

Provider synchronization now records:

- provider capabilities
- the canonical AI command catalog
- the generated provider manifest version

This gives downstream provider integrations a stable description of what OrchestraX exposes without coupling the core command definitions to a provider.

## CLI separation

The CLI remains a secondary interface for diagnostics and administration.

The command router can be exercised from the CLI through:

```text
neo command "/package-selector for MoneyMap"
```

This is a diagnostic bridge to the AI Command system, not the AI command language itself.
