# V0.5.0 — Syntra

V0.5 introduces **Syntra**, the internal persistent project-intelligence and context storage subsystem of Neo OrchestraX.

## User boundary

Users interact with OrchestraX commands such as:

```text
@context
@context for MoneyMap
```

There is no `@syntra` command.

## Entry model

Each Syntra entry contains:

- id
- title
- content
- category
- status
- confidence
- source/provenance
- createdAt
- updatedAt

## Categories

- project
- architecture
- knowledge
- decision
- requirement
- constraint
- problem
- work

## Governance

- draft
- review
- confirmed
- rejected
- superseded

Agent-derived information can therefore remain non-authoritative until reviewed.

## Persistence

```text
<project>/
└── .orchestrax/
    └── syntra/
        └── entries.json
```

## Diagnostic CLI

```text
neo syntra init MoneyMap
neo syntra add MoneyMap "Architecture" "..." architecture
neo syntra list MoneyMap
neo syntra search MoneyMap "authentication"
neo syntra status MoneyMap <entry-id> confirmed
```

These are development diagnostics. The intended user experience remains through OrchestraX commands.
