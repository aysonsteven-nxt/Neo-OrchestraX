# V0.16.1 — Workspace / Project Hub Resolution Fix

Bugfix release for V0.16.0.

## Fixed

- A logical VS Code multi-root `.code-workspace` is now treated as a workspace boundary even when OrchestraX metadata has not yet been initialized.
- Project discovery can use the folders declared by that workspace file.
- Project Hub location follows the resolved workspace scope instead of blindly falling back to the project's parent directory.
- Native `neo pack install <pack> <project>` now reaches the same project pack installation path once the project is discovered correctly.
- AI Command compatibility `/package-install ... for <project>` uses the same corrected Project Hub location.

## Workspace rule

A workspace is a logical scope. Projects do not have to be physically located under the workspace directory. For projects that live outside the workspace directory, the workspace must still be explicitly discoverable/associated (for example through a multi-root `.code-workspace` when the CLI is invoked from that workspace context, or an initialized OrchestraX workspace association).

## Locked boundaries

- Native `neo ...` CLI remains the primary operational interface.
- No new AI Commands are introduced.
- React/Vite remains outside the OrchestraX repository and is still reserved for the generated Project Hub UI.
