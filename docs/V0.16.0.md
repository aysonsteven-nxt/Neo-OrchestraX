# V0.16.0 — Project Hub Foundation

V0.16.0 establishes the Project Hub as a project-local documentation and project-management surface generated by Neo OrchestraX.

## Locked boundaries

- Native `neo ...` CLI is the primary OrchestraX operational interface.
- No new AI commands are introduced after the V0.15.x AI Command compatibility layer.
- React, Vite, TypeScript UI source, and frontend dependencies are **not** part of the Neo OrchestraX installation repository.
- The Project Hub UI is a later release and will be generated inside the project's `<project>-docs` directory.
- The project repository does not receive the Project Manager pack itself.

## Workspace and Project Hub location

A workspace is a logical scope. It does not require projects to be physically
located underneath the workspace directory. A VS Code multi-root `.code-workspace`
file is a valid workspace boundary, and `neo workspace init <path>` can initialize
OrchestraX metadata in any manually created workspace directory.

For an initialized workspace:

```text
workspace/
├── projects/
│   └── MoneyMap/
└── MoneyMap-docs/
    ├── hub.json
    ├── packs/
    ├── board/
    │   ├── board.json
    │   ├── schemas/
    │   ├── epics/
    │   ├── stories/
    │   └── subtasks/
    ├── discussions/
    └── architecture/       # added when Solutions Architect is installed
```

## Project Manager pack v0.3.0

The Project Manager pack contains three first-class agents:

- `product-owner`
- `scrum-master`
- `customer-journey-expert`

It also contains the project-management skills for requirements, stories, acceptance criteria, backlog management, Scrum, and customer journey analysis.

The resolved pack is installed under `<project>-docs/packs/project-manager`, not under the project repository's `.orchestrax/packs` directory. The `<project>-docs` directory is created at the workspace root when a workspace is resolved; it is not derived from the project's parent directory.

## Project management model

```text
Epic
└── User Story
    └── Subtask
```

User Stories support descriptions, acceptance criteria, priority, status, subtasks, and discussion comments. The filesystem remains the source of truth.

## Solutions Architect integration

`solutions-architect@0.3.0` requires `project-manager@^0.3.0` and extends the existing Project Hub with:

```text
<project>-docs/architecture/architecture.json
```

It does not create a second hub.

## CLI

New foundation commands:

```text
neo hub status <project>
neo hub path <project>
```

Existing pack installation automatically creates/extends the Project Hub when a project-scoped Project Manager or Solutions Architect pack is installed.
